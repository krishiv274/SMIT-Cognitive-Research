## 2. Full-length dry run with the default configuration

Configuration `SMIT-v1-9e42ee6f` (500 ms fixation, 500 ms memory stimulus, 3,000 ms interference, 1,000 ms retention, 2,000 ms deadline, 800–1,200 ms ITI, 6 + 60 trials), run in pilot mode by an automated in-page participant (`frontend/tests/03_dry_run_default_config.spec.ts`; summary produced with `scripts/summarize_dry_run.py`).

The full-length run was executed three times (all 66/66 trials saved and `completed` each time; the first two runs ended with a failure in the *test script's* final dashboard-screenshot step, which was then fixed). Timing-quality flags per run: run 1 — 64 `ok`, 2 `warning`; run 2 — 66 `ok`; run 3 — 59 `ok`, 7 `warning`; **0 `invalid` in all runs**. Warnings were caused by occasional long frame intervals (dropped frames) detected by the engine; phase durations stayed within one frame. The complete per-trial log of run 3 is `pilot/dry_run_timing_log.json`.

- Recognition responses recorded on 60/60 trials (automated presses 400–720 ms after probe onset; recorded RTs 389–735 ms); secondary responses on 40/40 interference trials; 11 dropped-frame events across 7 trials.
- Duration of the run: ≈ 8.3 minutes for 66 trials including two breaks (≈ 10 minutes for a real participant including reading time).

**Interpretation and caution.** Headless Chromium drives `requestAnimationFrame` from a regular simulated 60 Hz clock, so these figures verify the **scheduling logic** (whole-frame phases, onset bookkeeping, durations, data flow) — they do **not** measure the physical latency of a monitor, GPU or keyboard. ITI deviations of ±8 ms reflect rounding of a uniformly jittered planned value to whole frames (expected, ≤ half a frame).

### Behaviour on real hardware with a throttled tab (observed)

During manual checking in the desktop app's browser pane, a pilot session was run while the pane was hidden. The browser throttled animation frames (≈ 1 frame/s), stretching phases to 1,000–2,000 ms. **All six affected trials were automatically flagged `invalid`** by the timing-quality rules (and one also recorded focus loss), so they would be excluded from analysis. This confirms the safeguard and shows why participants must use a visible, focused, full-screen window.

## 3. Bugs discovered and fixes implemented

| # | Found by | Problem | Fix |
|---|---|---|---|
| 1 | Import tests | A formula typed into a data cell was never executed (safe) but was reported as "missing value", which is misleading | The importer now reads formulas without evaluating them and reports "formulas are not accepted in data cells" |
| 2 | Researcher E2E | Selecting the same file again after a failed upload did nothing (input value not reset) | File input is cleared after each selection |
| 3 | Analysis inspection | Hypothesis evidence read "p = < .001" | APA-style p formatting with the correct relation sign |
| 4 | Report inspection | Pairwise-comparison table columns too narrow in the PDF | Explicit column widths |
| 5 | Report review | A report built from synthetic data would look like a real final report | Automatic "SYNTHETIC TEST DATA — NOT RESEARCH FINDINGS" watermark when any participant ID starts with `SYN` |
| 6 | Engine tests | Test expected a mid-phase stall to lengthen a phase; the engine (correctly) absorbs it because phase ends are time-based | Test corrected; added a case with a stall exactly at stimulus offset, which is measured as a deviation |
| 7 | Dry-run harness | The first automated dry run stalled because the test script's polling raced with screen transitions (application unaffected; verified manually) | In-page automated participant with deterministic screen hand-offs |
| 8 | Statistics tests | A random test sample failed Shapiro–Wilk by chance, so the expected Pearson route switched to Spearman | Test uses deterministic normal quantiles for the method-selection check |

## 4. Remaining limitations

- **Real display/keyboard latency not measured.** Validate on the testing computer (pilot sessions show measured durations; a photodiode would be needed for lab-grade verification). Browser timing is not laboratory-grade.
- **Browsers:** E2E tests ran in Chromium only. Chrome/Edge are recommended; Firefox and Safari were not tested.
- **Docker:** `Dockerfile`/`docker-compose.yml` were written but not built (Docker daemon not running in this environment).
- **Windows/Linux setup scripts** (`setup.ps1`, `start.ps1`) were not executed (macOS only here).
- **Excel formulas** were verified with a Python formula engine (pycel), not in Microsoft Excel or LibreOffice; open the template in Excel once to confirm.
- **PostgreSQL** support is configuration-level only (SQLite tested).
- Automatically drafted Discussion/Conclusion text requires human review.
